# Starting configuration: i7 13th generation, 32 GB RAM, RTX 4060 8 GB

Use the existing one-job worker and batch size 1 in both candidate definitions. Load one model at a time. These are conservative starting settings, not a verified statement that every checkpoint/segment configuration fits in 8 GB or meets a particular latency target. Keep other GPU workloads closed during the first measurement.

1. Identify the host OS and NVIDIA driver with `nvidia-smi`. On Linux, configure NVIDIA Container Toolkit for Docker. On Windows, use a supported WSL2/Docker Desktop GPU setup. Follow the host-specific NVIDIA guide; a Windows GPU installation is not interchangeable with a native Linux installation.
2. Choose an official PyTorch CUDA wheel index supported by the installed driver. The initializer deliberately requires this explicitly for CUDA instead of assuming a compatible driver.
3. Initialize the private deployment configuration. For example, **only after confirming CUDA 12.8 wheel compatibility**:

```bash
python3 tools/init_deploy.py --origin https://karaoke.example.com --device cuda --torch-index-url https://download.pytorch.org/whl/cu128
```

If `deploy/.env` already exists, edit its device and wheel index locally while keeping the existing credentials. The initializer will not overwrite it.

4. Build and test actual GPU execution inside the worker image:

```bash
docker compose --env-file deploy/.env -f compose.yaml -f compose.gpu.yaml build
docker compose --env-file deploy/.env -f compose.yaml -f compose.gpu.yaml run --rm --no-deps worker python -m sonara_vocal_remover.jobs.gpu_check
```

The check executes a small CUDA matrix multiplication and reports GPU name, CUDA/PyTorch versions and visible free/total VRAM. It fails if CUDA cannot run. It does not certify model memory usage or audio quality. The worker build installs PyTorch, torchvision and torchaudio from the same selected index and constrains the second dependency installation to those exact versions, preventing a later dependency from silently replacing the selected wheel variants.

5. Prepare both models and start using the NVIDIA commands in [README.md](README.md). Run a representative full song three times per model with `tools/benchmark_karaoke.py`, and compare latency plus perceived vocal leakage. Do not increase parallel workers before measuring peak VRAM and queue behavior on this host.

On out-of-memory errors, check competing GPU programs and model segment/batch parameters before retrying. Do not claim a fast mode or automatically change the checkpoint to conceal a failure. A smaller-segment configuration should have its own model ID/receipt and a listening test before becoming the default.

Sources: [PyTorch installation variants](https://pytorch.org/get-started/previous-versions/), [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html), [NVIDIA CUDA on WSL](https://docs.nvidia.com/cuda/wsl-user-guide/index.html).
